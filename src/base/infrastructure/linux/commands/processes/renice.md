# renice

**Уровень:** Средний

Изменяет приоритет уже запущенного процесса.

## Синтаксис

```bash
renice корректировка [-p PID] [-u пользователь] [-g группа]
```

## Опции

| Опция | Описание |
|-------|----------|
| `-p PID` | Изменить приоритет процесса |
| `-u пользователь` | Изменить приоритет процессов пользователя |
| `-g группа` | Изменить приоритет процессов группы |

## Приоритеты

| Значение | Описание |
|----------|----------|
| `-20` | Наивысший приоритет |
| `0` | Обычный приоритет |
| `19` | Наименьший приоритет |

## Примеры

### Изменить приоритет процесса

```bash
renice 10 -p 1234
```

### Повысить приоритет (root)

```bash
sudo renice -5 -p 1234
```

### Понизить приоритет всех процессов пользователя

```bash
renice 15 -u www-data
```

### Изменить приоритет группы процессов

```bash
renice 10 -g developers
```

### Несколько процессов

```bash
renice 5 -p 1234 -p 5678 -p 9012
```

### Проверить текущий приоритет

```bash
ps -o pid,ni,cmd -p 1234
```

### Установить минимальный приоритет

```bash
renice 19 -p 1234
```

### Установить максимальный приоритет (root)

```bash
sudo renice -20 -p 1234
```

### Все процессы пользователя

```bash
renice 10 -u backup-user
```

### Изменить приоритет процесса Java

```bash
renice 5 -p $(pidof -s java)
```

### renice в мониторинге

```bash
for pid in $(pgrep -u heavy-user); do
    renice 15 -p "$pid"
done
```

### Понизить приоритет фоновых задач

```bash
renice 19 -p $(pgrep -f "background-worker")
```

### Повысить приоритет критического сервиса

```bash
sudo renice -10 -p $(pidof -s critical-service)
```

## Практические сценарии

### Балансировка нагрузки

```bash
# Снизить приоритет тяжёлых процессов
for pid in $(pgrep -f "heavy-task"); do
    renice 15 -p "$pid"
done
```

### Приоритет для игрового сервера

```bash
sudo renice -15 -p $(pidof -s gameserver)
```

### Скрипт авторегулировки

```bash
#!/bin/bash
LOAD=$(awk '{print $1}' /proc/loadavg)
if (( $(echo "$LOAD > 5" | bc -l) )); then
    renice 19 -p $(pgrep -u batch-user)
fi
```

:::tip
Обычные пользователи могут только понижать приоритет (увеличивать niceness). Только root может повышать приоритет.
:::

:::warning
Изменение приоритета не влияет на уже выполняющийся квант времени. Эффект проявится при следующем планировании.
:::
