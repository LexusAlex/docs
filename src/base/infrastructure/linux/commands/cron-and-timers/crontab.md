# crontab

Планировщик задач cron — управление расписанием выполнения команд.

## Синтаксис

```bash
crontab [-u user] file
crontab [-u user] [-l | -r | -e | -i]
```

## Опции

| Опция | Описание |
|-------|----------|
| `-e` | Редактировать crontab текущего пользователя |
| `-l` | Вывести содержимое crontab |
| `-r` | Удалить crontab текущего пользователя |
| `-i` | Интерактивное подтверждение при удалении |
| `-u user` | Указать пользователя (только root) |

## Формат записей

```
минута час_дня день_месяц месяц день_недели команда
  *      *        *        *       *        команда
```

| Поле | Диапазон | Примеры |
|------|----------|---------|
| Минуты | 0-59 | `0`, `*/5`, `15,45` |
| Часы | 0-23 | `0`, `*/2`, `8-17` |
| День месяца | 1-31 | `1`, `15`, `*/10` |
| Месяц | 1-12 | `1`, `6-8`, `*/3` |
| День недели | 0-7 (0=7=Вс) | `0`, `1-5`, `Fri` |

## Специальные строки

| Строка | Эквивалент | Описание |
|--------|-----------|----------|
| `@reboot` | — | При загрузке системы |
| `@hourly` | `0 * * * *` | Каждый час |
| `@daily` | `0 0 * * *` | Раз в день (полночь) |
| `@weekly` | `0 0 * * 0` | Раз в неделю (воскресенье) |
| `@monthly` | `0 0 1 * *` | Раз в месяц (1-е число) |
| `@yearly` | `0 0 1 1 *` | Раз в год (1 января) |

## Примеры

### 1. Редактирование crontab

```bash
crontab -e
```

### 2. Просмотр текущих заданий

```bash
crontab -l
```

### 3. Просмотр crontab другого пользователя

```bash
sudo crontab -u alex -l
```

### 4. Удаление crontab

```bash
crontab -r
crontab -i -r   # с подтверждением
```

### 5. Ежедневный бэкап в 2:30 ночи

```bash
30 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
```

### 6. Каждые 15 минут

```bash
*/15 * * * * /usr/local/bin/check-health.sh
```

### 7. Очистка логов каждое воскресенье в 3:00

```bash
0 3 * * 0 find /var/log/app -name "*.log" -mtime +30 -delete
```

### 8. Рабочие дни с 9 до 17 каждый час

```bash
0 9-17 * * 1-5 /usr/local/bin/send-report.sh
```

### 9. Первое число каждого месяца

```bash
0 0 1 * * /usr/local/bin/monthly-cleanup.sh
```

### 10. С использованием @reboot

```bash
@reboot /usr/local/bin/start-services.sh &
```

### 11. Запуск скрипта загрузки с crontab

```bash
# Загрузить crontab из файла
crontab my-schedule.txt
```

### 12. Каждые 5 минут с перенаправлением вывода

```bash
*/5 * * * * /usr/local/bin/sync.sh > /dev/null 2>&1
```

### 13. С переменными окружения

```bash
MAILTO=admin@example.com
PATH=/usr/local/bin:/usr/bin:/bin
SHELL=/bin/bash
0 2 * * * /usr/local/bin/backup.sh
```

### 14. Экранирование символа %

```bash
0 2 * * * /usr/bin/date +\%Y-\%m-\%d > /tmp/date.txt
```

## Практические сценарии

### Мониторинг доступности сервера

```bash
*/2 * * * * /usr/local/bin/check-server.sh || echo "Server down" | mail -s "Alert" admin@example.com
```

### Автоматическое обновление системы

```bash
0 3 * * 0 apt-get update && apt-get -y upgrade >> /var/log/auto-update.log 2>&1
```

### Ротация собственных логов

```bash
0 0 * * * gzip /var/log/myapp/app.log.$(date -d yesterday +\%Y\%m\%d)
```

## Системные директории cron

| Путь | Назначение |
|------|-----------|
| `/etc/cron.d/` | Дополнительные файлы расписания |
| `/etc/cron.daily/` | Скрипты, выполняемые ежедневно |
| `/etc/cron.hourly/` | Скрипты, выполняемые ежечасно |
| `/etc/cron.weekly/` | Скрипты, выполняемые еженедельно |
| `/etc/cron.monthly/` | Скрипты, выполняемые ежемесячно |
| `/etc/crontab` | Системный crontab |
| `/var/spool/cron/` | Пользовательские crontab-файлы |

## Anacron

Anacron обеспечивает выполнение пропущенных задач (для систем, которые не работают 24/7):

```bash
# /etc/anacrontab
1   5   daily-backup   /usr/local/bin/backup.sh
7   10  weekly-report  /usr/local/bin/report.sh
```

:::tip Cron vs Systemd Timers
На современных системах с systemd рекомендуется использовать **systemd timers** вместо cron. Timers поддерживают логирование через journald, зависимости между юнитами, точный контроль расписания и мониторинг состояния.
:::

:::warning Права доступа
Файл `/etc/cron.allow` определяет, кто может использовать crontab. Если файл существует, только перечисленные пользователи имеют доступ. Если существует только `/etc/cron.deny` — все пользователи, кроме перечисленных, имеют доступ.
:::

## Безопасность

- Ограничьте доступ через `/etc/cron.allow` и `/etc/cron.deny`
- Не храните пароли в командах crontab
- Используйте абсолютные пути к командам
- Перенаправляйте вывод в лог-файлы
- Проверяйте права на исполняемые скрипты

## Советы

:::tip Отладка crontab
Проверьте синтаксис crontab онлайн или используйте `crontab -l | crontab -` для валидации. Для тестирования запустите команду вручную перед добавлением в расписание.
:::

:::warning Переменные окружения
Cron выполняет команды с минимальным набором переменных окружения. Всегда указывайте `PATH`, `SHELL` и другие необходимые переменные в начале crontab.
:::
