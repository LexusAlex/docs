# ltrace

**Уровень:** Продвинутый

Трассировка вызовов библиотек (динамических).

## Синтаксис

```bash
ltrace [options] command [args]
ltrace [options] -p PID
```

## Опции

| Опция | Описание |
|-------|----------|
| `-e filter` | Фильтр вызовов библиотек |
| `-f` | Следовать за дочерними процессами |
| `-p PID` | Присоединиться к процессу |
| `-c` | Подсчёт вызовов |
| `-S` | Также показывать системные вызовы |
| `-n indent` | Отступ для вложенных вызовов |
| `-o file` | Вывод в файл |
| `-s len` | Максимальная длина строк |
| `-r` | Относительные метки времени |
| `-t` | Временные метки |
| `-tt` | Метки с микросекундами |
| `-ttt` | Epoch timestamp |
| `-L` | Не скрывать внутренние вызовы |
| `-n N` | Отступ для вложенных вызовов |
| `-b` | Не показывать PLT |

## Примеры

### 1. Трассировка команды

```bash
ltrace ls /tmp
```

### 2. Присоединение к процессу

```bash
sudo ltrace -p 1234
```

### 3. Подсчёт вызовов

```bash
ltrace -c ls -la
```

### 4. Системные вызовы тоже

```bash
ltrace -S ls /tmp
```

### 5. Фильтр по функции

```bash
ltrace -e malloc+free ls /tmp
```

### 6. Фильтр по библиотеке

```bash
ltrace -e libc.so ls /tmp
```

### 7. Запись в файл

```bash
ltrace -o trace.log ./myapp
```

### 8. Следование за детьми

```bash
ltrace -f bash -c 'echo test'
```

### 9. Увеличение длины строк

```bash
ltrace -s 200 cat /etc/passwd
```

### 10. Трассировка с временными метками

```bash
ltrace -tt ./myapp
```

### 11. Только имена функций

```bash
ltrace -e puts ./myapp
```

### 12. Исключение функций

```bash
ltrace -e !memcpy ./myapp
```

### 13. Отступ для вложенности

```bash
ltrace -n 2 ./myapp
```

### 14. Трассировкаопределённной функции

```bash
ltrace -e getenv bash -c 'echo $HOME'
```

### 15. Проверка утечек памяти (паттерн)

```bash
ltrace -e malloc,free,realloc ./myapp 2>&1 | grep -c "malloc\|free"
```

## ltrace vs strace

| Особенность | ltrace | strace |
|-------------|--------|--------|
| Уровень | Библиотеки | Ядро |
| Перехват | Динамические вызовы | Системные вызовы |
| Статические программы | Нет | Да |
| Производительность | Менее overhead | Более overhead |
| Отладка | Библиотечные функции | Взаимодействие с ядром |

## Практические сценарии

### Отладка работы с памятью

```bash
ltrace -e malloc,free,realloc,calloc ./app 2>&1
```

### Проверка строковых операций

```bash
ltrace -e strcmp,strlen,strcpy,strcat ./app
```

### Анализ работы с файлами

```bash
ltrace -e fopen,fread,fwrite,fclose ./app
```

### Проверка системных вызовов (с -S)

```bash
ltrace -S ./app 2>&1 | head -100
```

### Профилирование вызовов

```bash
ltrace -c ./app 2>&1
```

## Анализ вывода

```
libcrypto.so->EVP_DigestInit(0x7ffd1234, 0x5555, 0, 0) = 0
libcrypto.so->EVP_DigestUpdate(0x7ffd1234, 0x5555, 32, 0) = 0
libcrypto.so->EVP_DigestFinal(0x7ffd1234, 0x7ffd5678, 0) = 0
```

| Часть | Описание |
|-------|----------|
| `libcrypto.so` | Библиотека |
| `EVP_DigestInit` | Функция |
| Аргументы | Параметры вызова |
| `= 0` | Возвращаемое значение |

:::tip Статические программы
ltrace не работает со статически скомпилированными программами. Используйте strace или debugfs.
:::

:::warning Без символов
Если программа скомпилирована без символов (`-s`), ltrace покажет только адреса, а не имена функций. Используйте `-e` с полными именами.
:::

## Советы

:::tip Анализ утечек
Сравните количество `malloc` и `free` вызовов. Используйте valgrind для точного анализа.
:::

:::warning Безопасность
ltrace может перехватывать вызовы, содержащие пароли. Не используйте на production без необходимости.
