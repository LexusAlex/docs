# ln

Создаёт ссылки на файлы и каталоги. Поддерживает два типа: жёсткие (hard links) и символические (symbolic links, symlinks).

## Синтаксис

```bash
ln [опции] источник назначение
ln [опции] источник... каталог
ln -s источник назначение          # символическая ссылка
ln -s -t каталог источник...       # создать ссылки в каталоге
```

## Основные опции

| Опция | Описание |
|-------|----------|
| `-s`, `--symbolic` | Создать символическую ссылку |
| `-f`, `--force` | Принудительно перезаписать существующий файл |
| `-i`, `--interactive` | Спрашивать перед перезаписью |
| `-n`, `--no-dereference` | Не следовать по ссылке в назначении |
| `-v`, `--verbose` | Подробный вывод |
| `-d`, `-F` | Разрешить создание жёстких ссылок на каталоги (только root) |
| `-T` | Обрабатывать назначение как обычный файл |
| `--backup` | Создать резервную копию перед перезаписью |
| `-b` | Как `--backup`, но с суффиксом `~` |
| `-S суффикс` | Задать суффикс для резервных копий |
| `-r` | Создать символические ссылки относительно расположения ссылки |
| `-L` | Разыменовать символические ссылки в источнике |
| `-P` | Не следовать символическим ссылкам в источнике |

## Жёсткие ссылки vs символические

```
Жёсткая ссылка (hard link):
┌─────────────┐
│ inode 12345 │
└──────┬──────┘
       │
  ┌────┴────┐
  │         │
file.txt  hardlink.txt
(оба указывают на один и тот же inode)

Символическая ссылка (symbolic link):
┌──────────────┐     ┌──────────────┐
│ symlink.txt  │────▶│  file.txt    │
│ inode 12346  │     │  inode 12345 │
└──────────────┘     └──────────────┘
(ссылка хранит путь к оригиналу)
```

| Характеристика | Жёсткая ссылка | Символическая ссылка |
|---------------|----------------|---------------------|
| Тип | Другое имя того же inode | Отдельный файл с путём |
| Каталоги | Нельзя (без root) | Можно |
| Разные ФС | Нельзя | Можно |
| Удаление оригинала | Ссылка работает | Ссылка битая |
| Размер | 0 (не занимает места) | Размер строки пути |
| `ls -l` | Обычный файл | Показывает `->` |
| inode | Тот же | Другой |

## Примеры

### 1. Создание жёсткой ссылки

```bash
ln file.txt hardlink.txt
ls -li file.txt hardlink.txt
# 131073 -rw-r--r-- 2 alex alex 1024 Jan 15 10:30 file.txt
# 131073 -rw-r--r-- 2 alex alex 1024 Jan 15 10:30 hardlink.txt
# Одинаковый inode, количество ссылок = 2
```

### 2. Создание символической ссылки

```bash
ln -s file.txt symlink.txt
ls -la symlink.txt
# lrwxrwxrwx 1 alex alex 8 Jan 15 10:30 symlink.txt -> file.txt
```

### 3. Символическая ссылка на каталог

```bash
ln -s /var/log /tmp/logs
ls -la /tmp/logs
# lrwxrwxrwx 1 alex alex 8 Jan 15 10:30 logs -> /var/log
```

### 4. Создание нескольких ссылок в каталоге

```bash
ln -s /usr/bin/python3 /usr/local/bin/python
ln -s -t /usr/local/bin/ /usr/bin/node /usr/bin/npm
```

### 5. Принудительное перезаписывание

```bash
ln -sf new_target.txt existing_link
# Перезаписывает существующую ссылку
```

### 6. Интерактивное создание

```bash
ln -si file.txt link.txt
# ln: replace 'link.txt'? (y/n)
```

### 7. Не следовать по ссылке в назначении

```bash
ln -snf new_target.txt link.txt
# Заменяет ссылку, даже если link.txt уже является ссылкой
```

### 8. Относительные символические ссылки

```bash
ln -sr ./config/app.conf /etc/myapp.conf
# Создаёт относительную ссылку
readlink /etc/myapp.conf
# ../home/user/config/app.conf
```

### 9. Проверка, является ли файл ссылкой

```bash
if [[ -L symlink.txt ]]; then
    echo "Это символическая ссылка"
    readlink symlink.txt  # показать цель
fi
```

### 10. Создание резервных ссылок

```bash
ln --backup file.txt link.txt
# Создаёт link.txt~ перед перезаписью
```

### 11. Ссылка на несуществующий файл

```bash
ln -s /nonexistent broken_link
ls -la broken_link
# lrwxrwxrwx 1 alex alex 12 Jan 15 10:30 broken_link -> /nonexistent
# Ссылка существует, но цель нет
```

### 12. Удаление ссылки

```bash
rm symlink.txt
# Удаляет ссылку, не затрагивая оригинал

unlink symlink.txt
# Альтернативная команда для удаления ссылки
```

### 13. Поиск всех ссылок на файл

```bash
find / -samefile file.txt -ls
# Найти все жёсткие ссылки на файл

find / -type l -lname '*target*' 2>/dev/null
# Найти символические ссылки, указывающие на target
```

### 14. Копирование с сохранением ссылок

```bash
cp -a source/ dest/
# -a сохраняет символические ссылки как ссылки
```

### 15. Создание ссылки в текущем каталоге

```bash
ln -s /full/path/to/file .
# Ссылка в текущем каталоге с тем же именем
```

## Практические сценарии

### Управление версиями программ

```bash
sudo ln -sf /usr/bin/python3.11 /usr/bin/python3
sudo ln -sf /usr/bin/python3.11 /usr/bin/python
```

### Структура конфигов

```bash
ln -sf /etc/nginx/sites-available/mysite /etc/nginx/sites-enabled/mysite
```

### Развёртывание приложения

```bash
# Симлинк на текущую версию
ln -sfn /opt/myapp/v2.1.0 /opt/myapp/current
# Обновление просто меняет цель ссылки
```

### Общие библиотеки

```bash
sudo ln -s /usr/local/lib/libcustom.so /usr/lib/libcustom.so
sudo ldconfig
```

## Советы

:::tip
Используйте `ln -sr` для создания относительных ссылок — это делает структуру переносимой между системами.
:::

:::warning
При удалении оригинала жёсткой ссылки данные не удаляются, пока существуют другие жёсткие ссылки на тот же inode. Символическая ссылка становится «битой».
:::

:::tip
Для управления версиями приложений используйте паттерн: `ln -sfn /opt/app/v2.0 /opt/app/current`. Обновление = смена цели ссылки.
:::

:::warning
Жёсткие ссылки не могут указывать на каталоги (без root) и не могут пересекать границы файловых систем. Используйте символические ссылки для этих случаев.
:::
