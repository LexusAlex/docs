# Парсинг HTML, CSS и JavaScript

Когда браузер получает ответ от сервера, он преобразует сырые байты в структуры данных, с которыми можно работать.

## Общий процесс

```
Байты → Символы → Токены → DOM / CSSOM → Render Tree → Layout → Paint → Composite
```

## Парсинг HTML → DOM

HTML-документ парсится **инкрементально** — браузер не ждёт загрузки всего документа, а начинает обработку по мере поступления данных.

### Этапы

1. **Декодирование** — байты преобразуются в символы (UTF-8, ISO-8859-1 и т.д.)
2. **Токенизация** — символы разбиваются на токены: открывающие теги, закрывающие теги, атрибуты, текст
3. **Построение DOM** — из токенов формируется дерево объектов (Document Object Model)

```html
<html>
  <body>
    <h1>Привет</h1>
    <p>Мир</p>
  </body>
</html>
```

Результат — дерево с узлами: `Document → html → body → h1, p`.

::: info
HTML-парсинг устойчив к ошибкам. Если тег закрыт неправильно или отсутствует, парсер попытается восстановить структуру автоматически.
:::

## Парсинг CSS → CSSOM

CSS парсится **параллельно** с HTML, но блокирует рендеринг до полной загрузки.

### Этапы

1. **Декодирование** — аналогично HTML
2. **Токенизация** — разбор на селекторы, свойства, значения
3. **Построение CSSOM** — формирование CSS Object Model с учётом каскадности и наследования

```css
body {
  font-size: 16px;
}
h1 {
  color: blue;
}
```

CSSOM — это дерево, где каждый узел содержит вычисленные стили. Стили наследуются и перезаписываются согласно специфичности.

::: warning
Браузер не может отрисовать страницу, пока не загрузит и не обработает все CSS. Поэтому `<link rel="stylesheet">` блокирует рендеринг.
:::

## Парсинг JavaScript

JavaScript парсится и выполняется с учётом нескольких нюансов.

### Синхронное выполнение

По умолчанию JavaScript блокирует парсинг HTML:

```html
<script src="app.js"></script>
<!-- HTML-парсинг暂停直到 app.js загрузится и выполнится -->
```

### Атрибуты `async` и `defer`

```html
<!-- Загружается параллельно, выполняется сразу после загрузки -->
<script async src="analytics.js"></script>

<!-- Загружается параллельно, выполняется после DOM готов -->
<script defer src="app.js"></script>
```

| Поведение | Обычный | `async` | `defer` |
|-----------|---------|---------|---------|
| Параллельная загрузка | Нет | Да | Да |
| Блокирует HTML-парсинг | Да | Нет | Нет |
| Время выполнения | Сразу | Сразу после загрузки | После DOMContentLoaded |

### JIT-компиляция

Современные движки (V8, SpiderMonkey) используют **JIT-компиляцию**:

1. **Парсинг** — исходный код → AST (абстрактное синтаксическое дерево)
2. **Байткод** — AST → промежуточное представление
3. **Оптимизация** — горячие участки компилируются в нативный код

## Параллельность загрузки

Сканер предварительной загрузки (preload scanner) работает вместе с основным парсером:

1. Основной парсер遇到 `<script>` и останавливается
2. Сканер просматривает остальной HTML и находит ресурсы для загрузки (`<img>`, `<link>`, `<script>`)
3. Ресурсы загружаются параллельно, пока основной парсер ждёт выполнения скрипта

::: tip
Размещайте `<script>` перед `</body>` или используйте `defer`, чтобы не блокировать парсинг HTML.
:::
