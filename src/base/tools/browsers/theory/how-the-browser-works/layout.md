# Стилизация и макетирование

После построения DOM и CSSOM браузер формирует **дерево рендеринга**, вычисляет геометрию элементов и отрисовывает их на экране.

## Render Tree

Дерево рендеринга объединяет DOM и CSSOM. В него попадают только **видимые** элементы:

- `display: none` — исключаются из дерева
- `visibility: hidden` — присутствуют в дереве, но не отрисовываются
- `<head>`, `<script>`, `<meta>` — не имеют визуального представления

```
DOM + CSSOM → Render Tree
```

Каждый узел дерева рендеринга — это прямоугольник с вычисленными стилями.

## Layout (Reflow)

Этап **layout** вычисляет точный размер и позицию каждого элемента в пикселях.

### Что вычисляется

- Ширина и высота элемента
- Позиция относительно viewport и родительского элемента
- Отступы (margin, padding, border)

### Box Model

Каждый элемент — это прямоугольник:

```
┌─────────────────────────┐
│         margin          │
│  ┌───────────────────┐  │
│  │     border        │  │
│  │  ┌─────────────┐  │  │
│  │  │  padding     │  │  │
│  │  │  ┌───────┐  │  │  │
│  │  │  │content│  │  │  │
│  │  │  └───────┘  │  │  │
│  │  └─────────────┘  │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

### Что вызывает reflow

- Изменение размеров элемента (`width`, `height`, `padding`, `border`)
- Добавление/удаление элементов из DOM
- Изменение содержимого (текст, изображения)
- Изменение `position`, `display`, `float`
- Изменение `font-size`, `line-height`

::: warning
Reflow — дорогая операция. При изменении одного элемента браузер может пересчитать layout для всех потомков и соседей.
:::

## Paint (Rasterization)

После layout браузер знает **где** рисовать. Этап **paint** определяет **что** рисовать.

### Порядок отрисовки

1. `background` (цвет, изображения)
2. `border`
3. `box-shadow`
4. `outline`
5. Текст
6. Изображения

### Paint Order

Свойство `paint-order` позволяет менять порядок:

```css
h1 {
  paint-order: stroke fill;
  /* Сначала обводка, потом заливка */
}
```

### Слои (Layers)

Некоторые элементы создаются в отдельных слоях:

- `position: fixed`
- `opacity` с анимацией
- `transform`
- `will-change`
- `<video>`, `<canvas>`
- Элементы с `z-index` в контексте наложения

::: tip
Используйте `will-change: transform` или `transform: translateZ(0)` для выноса элемента в отдельный слой — это ускоряет анимации.
:::

## Composite

Последний этап — **композиция**. Браузер объединяет все слои в правильном порядке и отображает результат на экране.

### Порядок композиции

Слои отрисовываются в порядке `z-index` и порядка появления в DOM:

```
Слой 1 (z-index: 0)  →  Слой 2 (z-index: 1)  →  Слой 3 (z-index: 2)
                              ↓
                        Финальное изображение на экране
```

### Почему слои важны

Без отдельных слоев при изменении `top` или `left` браузер выполняет **reflow + paint + composite**.

С отдельным слоем при изменении `transform` выполняется только **composite** — это намного быстрее.

```css
/* Медленно — вызывает reflow */
.animated {
  left: 100px;
}

/* Быстро — только composite */
.animated {
  transform: translateX(100px);
}
```

## Полный цикл рендеринга

```
1. DOM (парсинг HTML)
2. CSSOM (парсинг CSS)
3. Render Tree (DOM + CSSOM)
4. Layout (геометрия)
5. Paint (отрисовка)
6. Composite (объединение слоёв)
7. Отображение на экране
```

Браузер стремится выполнять этот цикл **60 раз в секунду** (16.6 мс на кадр) для плавной анимации.
