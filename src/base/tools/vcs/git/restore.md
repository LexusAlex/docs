# git restore

**Уровень:** Начинающий
**Версия Git:** 2.23.0
**Версия документации:** 1.0

Восстанавливает файлы рабочей директории из указанного источника (коммит, индекс или другая ветка). Появился в Git 2.23 как замена части функциональности `git checkout` для восстановления файлов. Безопасная альтертернатива — не переключает ветки.

## Синтаксис

```bash
git restore [<options>] [--] <pathspec>...
git restore [<options>] --source=<tree> [--] <pathspec>...
git restore (-p | --patch) [<options>] [--] [<pathspec>...]
```

## Основные опции

| Опция | Описание |
|-------|----------|
| `--source=<tree>` | Восстановить из указанного дерева (коммит, ветка, тег). По умолчанию — индекс |
| `--staged` | Восстановить файл в индексе (отменить `git add`) |
| `--worktree` | Восстановить файл в рабочей директории |
| `--patch` | Интерактивно выбрать hunks для восстановления |
| `--ours` | При конфликте использовать нашу версию |
| `--theirs` | При конфликте использовать их версию |
| `--merge` | Восстановить файл, используя merge-стратегию |
| `--conflict=<style>` | Выбрать стиль отображения конфликтов (merge, diff3, zdiff3) |
| `--ignore-unmerged` | Игнорировать неслитые файлы |
| `--recurse-submodules` | Рекурсивно восстановить подмодули |
| `--overlay` | Не удалять файлы, отсутствующие в источнике |
| `--pathspec-from-file=<file>` | Прочитать pathspec из файла |
| `-q`, `--quiet` | Подавить вывод |
| `--progress` | Показать прогресс |

## Примеры

### 1. Восстановить файл из индекса (по умолчанию)

```bash
# Отменить изменения в рабочей директории для файла
git restore file.txt
```

### 2. Восстановить файл из конкретного коммита

```bash
# Взять версию файла из коммита abc1234
git restore --source=abc1234 file.txt
```

### 3. Отменить `git add` (восстановить в индексе)

```bash
# Убрать файл из staging area
git restore --staged file.txt
```

### 4. Восстановить и в индексе, и в рабочей директории

```bash
# Полностью отменить изменения файла
git restore --staged --worktree file.txt
```

### 5. Восстановить конкретный файл из HEAD

```bash
# Вернуть файл к последнему закоммиченному состоянию
git restore HEAD -- src/app.js
```

### 6. Восстановить все файлы в директории

```bash
# Отменить все изменения в директории src/
git restore src/
```

### 7. Восстановить все изменённые файлы

```bash
# Отменить все изменения в рабочей директории
git restore .
```

### 8. Интерактивное восстановление (--patch)

```bash
# Выбрать конкретные hunks для восстановления
git restore --patch file.txt
```

### 9. Восстановить файл из другой ветки

```bash
# Взять файл из ветки feature
git restore --source=feature -- src/utils.js
```

### 10. Восстановить удалённый файл

```bash
# Если файл был удалён, восстановить из последнего коммита
git restore deleted_file.txt
```

### 11. Восстановить из тега

```bash
# Взять версию файла из тега v1.0
git restore --source=v1.0 -- config.yml
```

### 12. Восстановить с использованием "нашей" версии при конфликте

```bash
# При merge-конфликте выбрать нашу версию
git restore --ours conflicted_file.txt
```

### 13. Восстановить с использованием "их" версии при конфликте

```bash
# При merge-конфликте выбрать их версию
git restore --theirs conflicted_file.txt
```

### 14. Восстановить несколько файлов

```bash
# Восстановить несколько файлов сразу
git restore file1.txt file2.txt src/app.js
```

### 15. Восстановить с игнорированием неслитых файлов

```bash
# Пропустить файлы с конфликтами
git restore --ignore-unmerged file.txt
```

### 16. Восстановить с рекурсией по подмодулям

```bash
# Восстановить файлы в подмодулях
git restore --recurse-submodules -- .
```

### 17. Восстановить с overlay-режимом

```bash
# Не удалять файлы, отсутствующие в источнике
git restore --overlay --source=HEAD~3 -- .
```

### 18. Восстановить из pathspec-файла

```bash
# Список файлов в файле
git restore --pathspec-from-file=filelist.txt
```

### 19. Восстановить с конфликтами в стиле diff3

```bash
# Показать базовую версию при конфликтах
git restore --conflict=diff3 file.txt
```

### 20. Восстановить staged-файл из коммита

```bash
# Восстановить в индексе из конкретного коммита
git restore --staged --source=HEAD~2 -- file.txt
```

## Практические сценарии

### Отмена нежелательных изменений в рабочей директории

```bash
# Посмотреть, что изменилось
git diff
# Отменить изменения в определённых файлах
git restore src/app.js src/utils.js
```

### Отмена `git add` перед коммитом

```bash
# Случайно добавили файл в staging
git add .
# Убрать конкретный файл из индекса
git restore --staged secret.env
```

### Восстановление файла после случайного удаления

```bash
# Удалили файл, но ещё не закоммитили удаление
git restore path/to/deleted/file.txt
```

### Работа с merge-конфликтами

```bash
# При конфликте — выбрать одну из сторон
git restore --ours config.yml        # Наша версия
git restore --theirs config.yml      # Их версия
# Или восстановить с diff3-отображением
git restore --conflict=diff3 config.yml
```

## Связки с другими командами

```bash
# Diff + restore (посмотреть и отменить изменения)
git diff file.txt && git restore file.txt

# Status + restore (проверить и отменить)
git status && git restore --staged file.txt

# Log + restore (восстановить файл из старого коммита)
git log --oneline -- file.txt && git restore --source=abc1234 -- file.txt

# Stash + restore (временно убрать или отменить изменения)
git stash && git restore .
```

## Советы

:::tip Используйте вместо `git checkout -- <file>`
`git restore` — современная замена `git checkout -- <file>`. Синтаксис понятнее и меньше шансов ошибиться с переключением веток.
:::

:::warning `git restore .` отменяет все изменения
Команда `git restore .` отменяет все незакоммиченные изменения в рабочей директории. Убедитесь, что ничего важного не потеряется.
:::

:::tip `--staged` для отмены `add`
Если вы случайно сделали `git add`, используйте `git restore --staged <file>`, чтобы убрать файл из staging area.
:::

:::warning Восстановление необратимо
`git restore` перезаписывает файлы без предупреждения. Если изменения не были сохранены, они будут потеряны.
:::
