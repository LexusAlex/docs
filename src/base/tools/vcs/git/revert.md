# git revert

**Уровень:** Средний
**Версия Git:** 0.99
**Версия документации:** 1.0

Создаёт новый коммит, отменяющий изменения указанных коммитов. В отличие от `git reset`, не переписывает историю — безопасен для публичных веток. Каждый reverted-коммит создаёт обратный коммит в истории.

## Синтаксис

```bash
git revert [--[no-]edit] [-n] [-m parent-number] [-s] [-x] [--ff] [<commit>...]
git revert (--continue | --skip | --abort | --quit)
```

## Основные опции

| Опция | Описание |
|-------|----------|
| `--no-commit` | Выполняет revert без автоматического коммита (только изменяет индекс и рабочую директорию) |
| `--edit` | Открывает редактор для изменения сообщения коммита |
| `--mainline <n>` | Указывает номер родителя для revert merge-коммита (по умолчанию 1) |
| `--signoff` | Добавляет Signed-off-by строку в сообщение коммита |
| `--no-verify` | Пропускает pre-commit и commit-msg хуки |
| `-x` | Добавляет ссылку на оригинальный коммит в сообщение (полезно для cherry-pick) |
| `-m <parent-number>` | Указывает родительский коммит для merge-коммита |
| `--strategy-option <option>` | Передаёт опцию стратегии слияния |
| `--ff` | Если возможно, выполняет fast-forward |
| `-n`, `--no-commit` | Не создает коммит |
| `-q`, `--quiet` | Подавляет вывод |
| `--rerere-autoupdate` | Обновляет индекс с помощью rerere |

## Примеры

### 1. Отменить последний коммит

```bash
# Создаёт новый коммит, отменяющий изменения предыдущего
git revert HEAD
```

### 2. Отменить конкретный коммит по хешу

```bash
# Отменить коммит с определённым хешем
git revert abc1234
```

### 3. Отменить без автоматического коммита (--no-commit)

```bash
# Изменения попадут в staging, но коммит не создастся
git revert --no-commit HEAD
```

### 4. Отменить merge-коммит

```bash
# Указать номер родителя (обычно 1 для основной ветки)
git revert -m 1 merge_commit_hash
```

### 5. Отменить несколько коммитов сразу

```bash
# Отменить 3 последних коммита
git revert HEAD~2..HEAD
```

### 6. Отменить с редактированием сообщения

```bash
# Открыть редактор для изменения сообщения revert-коммита
git revert --edit abc1234
```

### 7. Отменить с добавлением Signed-off-by

```bash
# Добавить подпись в сообщение коммита
git revert --signoff abc1234
```

### 8. Отменить с ссылкой на оригинальный коммит (-x)

```bash
# В сообщение будет добавлено "This reverts commit abc1234"
git revert -x abc1234
```

### 9. Отменить несколько коммитов по одному

```bash
# Отменить диапазон коммитов, создавая отдельный revert для каждого
git revert older_commit..newer_commit
```

### 10. Отменить с пропуском хуков

```bash
# Пропустить pre-commit проверки
git revert --no-verify abc1234
```

### 11. Отменить merge с указанием второго родителя

```bash
# Использовать второго родителя как основу
git revert -m 2 merge_commit_hash
```

### 12. Отменить с опцией стратегии

```bash
# Использовать стратегию theirs для разрешения конфликтов
git revert --strategy-option theirs abc1234
```

### 13. Отменить диапазон коммитов (inclusive)

```bash
# Отменить от abc1234 до def5678 включительно
git revert abc1234..def5678
```

### 14. Отменить с fast-forward

```bash
# Если возможно, выполнить fast-forward
git revert --ff abc1234
```

### 15. Продолжить после разрешения конфликтов

```bash
# После разрешения конфликтов в revert
git add .
git revert --continue
```

### 16. Отменить revert (пропустить конфликт)

```bash
# Пропустить текущий revert при конфликтах
git revert --skip
```

### 17. Отменить начатый revert

```bash
# Прервать revert и вернуться к состоянию до
git revert --abort
```

### 18. Отменить несколько последних коммитов

```bash
# Отменить 5 последних коммитов
git revert --no-commit HEAD~5..HEAD
git commit -m "Отмена последних 5 коммитов"
```

### 19. Отменить с quiet-режимом

```bash
# Подавить вывод
git revert -q abc1234
```

## Практические сценарии

### Отмена бага в продакшене

```bash
# Найти коммит с багом
git log --oneline -20
# Отменить его с ссылкой на оригинал
git revert -x bad_commit_hash
# Отправить в удалённый репозиторий
git push origin main
```

### Отмена целого feature после merge

```bash
# Найти merge-коммит
git log --oneline --merges -5
# Отменить merge (взять первого родителя — основную ветку)
git revert -m 1 merge_commit_hash
git push origin main
```

### Групповая отмена нескольких коммитов

```bash
# Отменить несколько коммитов без промежуточных коммитов
git revert --no-commit HEAD~3..HEAD
git commit -m "Отмена изменений из PR #42"
```

### Отмена revert (возврат отменённых изменений)

```bash
# Если revert был ошибкой — revert revert-а
git revert revert_commit_hash
```

## Связки с другими командами

```bash
# Revert + push (отправить отмену в удалённый репозиторий)
git revert HEAD && git push origin main

# Revert нескольких коммитов одним коммитом
git revert --no-commit HEAD~3..HEAD && git commit -m "Отмена изменений"

# Найти коммит + отменить его
git log --oneline -10 && git revert abc1234

# Revert merge + восстановить ветку
git revert -m 1 merge_hash && git checkout feature && git merge main

# Revert + stash (если есть незакоммиченные изменения)
git stash && git revert HEAD && git stash pop
```

## Советы

:::tip Используйте revert вместо reset для публичных веток
`git revert` безопасен, так как не переписывает историю. Используйте его для отмены коммитов, которые уже были отправлены в удалённый репозиторий.
:::

:::warning Осторожно с revert merge-коммитов
При revert merge-коммита используйте `-m 1`, чтобы указать основного родителя. Неправильный выбор может привести к потере изменений.
:::

:::tip -x для отслеживаемости
Флаг `-x` автоматически добавляет "This reverts commit abc1234" в сообщение. Это помогает отслеживать, какие коммиты были отменены.
:::

:::warning Конфликты при revert
Если изменения пересекаются, revert может вызвать конфликты. Разрешите их, сделайте `git add` и `git revert --continue`.
:::
