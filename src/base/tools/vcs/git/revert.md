# git revert

**Уровень:** Средний
**Минимальная версия Git:** 0.99

`git revert` создаёт новый коммит, который отменяет изменения выбранного коммита. История не переписывается, поэтому это основной способ отмены уже опубликованных изменений.

## Синтаксис

```bash
git revert [<options>] <commit>...
git revert (--continue | --skip | --abort | --quit)
```

Обычно индекс и рабочее дерево должны быть чистыми. Если есть незакоммиченные изменения, сначала сохраните их коммитом или `git stash push`.

## Основные опции

| Опция | Описание |
|---|---|
| `-e`, `--edit` | Отредактировать сообщение revert-коммита |
| `--no-edit` | Не открывать редактор |
| `-n`, `--no-commit` | Применить обратные изменения в индекс и рабочее дерево без автоматического коммита |
| `-m <n>`, `--mainline <n>` | Для merge-коммита выбрать родителя, относительно которого вычислять отмену |
| `-s`, `--signoff` | Добавить строку `Signed-off-by` |
| `-S[<keyid>]`, `--gpg-sign[=<keyid>]` | Подписать новый коммит GPG/SSH-ключом |
| `--strategy <strategy>` | Выбрать стратегию слияния |
| `-X<option>` | Передать параметр стратегии |
| `--rerere-autoupdate` | Разрешить `rerere` обновить индекс после повторного разрешения конфликта |

У `git revert` нет опций `-x`, `--ff` и `--no-verify`. Они относятся к другим командам или не поддерживаются sequencer-командой.

## Примеры

### Отменить последний коммит

```bash
git status --short
git revert HEAD
```

Git создаст новый коммит и сохранит исходный коммит в истории.

### Отменить конкретный коммит

```bash
git show --stat a1b2c3d
git revert a1b2c3d
```

Перед отменой полезно проверить патч через `git show`.

### Отменить несколько коммитов одним итоговым коммитом

```bash
# Диапазон A^..B включает и A, и B
git revert --no-commit A^..B
git diff --cached
git commit -m "Revert changes from A through B"
```

Диапазон `A..B` не включает `A`. Если нужен ровно один новый коммит, используйте `--no-commit`, проверьте индекс и затем выполните `git commit`.

### Отменить merge-коммит

```bash
git show --no-patch --pretty='%H parents: %P' <merge-commit>
git revert -m 1 <merge-commit>
```

`-m 1` означает: оставить первого родителя основной линией и отменить результат, пришедший относительно него. Значения по умолчанию нет — для merge-коммита родителя нужно указать явно.

::: warning Влияние на будущие merge
Revert merge-коммита сообщает Git, что изменения этого merge больше не нужны. Последующее слияние той же ветки может не вернуть отменённые изменения. Часто сначала отменяют revert-коммит или создают новые коммиты с исправленным патчем.
:::

### Разрешить конфликт

```bash
git revert a1b2c3d
# исправьте конфликтующие файлы
git add path/to/resolved-file
git revert --continue
```

Другие варианты:

```bash
git revert --skip   # пропустить текущий коммит последовательности
git revert --abort  # вернуть состояние до начала всей операции
git revert --quit   # завершить sequencer, сохранив текущее состояние файлов
```

## Revert или reset

| Задача | Команда |
|---|---|
| Отменить опубликованный коммит | `git revert <commit>` |
| Убрать локальный последний коммит, сохранив изменения | `git reset --soft HEAD^` |
| Отменить незакоммиченные изменения файла | `git restore <file>` |
