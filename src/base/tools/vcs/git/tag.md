# git-tag

**Уровень:** Начинающий
**Версия Git:** 0.99

Создаёт, отображает, удаляет и проверяет объекты тегов в Git. Теги используются для маркировки определённых коммитов, обычно для указания версий выпуска.

## Синтаксис

```bash
git tag [опции] [имя_тега] [коммит]
git tag [опции] [имя_тега]
```

## Основные опции

| Опция | Описание |
|---|---|
| `-a` | Создать аннотированный тег |
| `-m <сообщение>` | Указать сообщение тега |
| `-d <тег>` | Удалить тег |
| `-l [шаблон]` | Список тегов с необязательным шаблоном |
| `-n[кол-во]` | Показать строки сообщения тега |
| `--sort=<ключ>` | Сортировать теги по указанному ключу |
| `--contains <коммит>` | Показать теги, содержащие коммит |
| `--no-contains <коммит>` | Показать теги, не содержащие коммит |
| `--merged <коммит>` | Показать теги, достижимые из коммита |
| `--no-merged <коммит>` | Показать теги, недостижимые из коммита |
| `--points-at <объект>` | Показать теги указанного объекта |
| `--creatordate` | Показать дату создания тега |
| `-s` | Создать подписанный тег GPG |
| `--verify` | Проверить подпись GPG тега |

## Примеры

1. Список всех тегов:
```bash
git tag
```

2. Список тегов с фильтрацией по шаблону:
```bash
git tag -l "v1.*"
```

3. Создание лёгкого тега (lightweight):
```bash
git tag v1.0.0
```

4. Создание аннотированного тега:
```bash
git tag -a v1.0.0 -m "Релиз версии 1.0.0"
```

5. Тегирование конкретного коммита:
```bash
git tag -a v0.9.0 abc1234 -m "Релиз версии 0.9.0"
```

6. Удаление локального тега:
```bash
git tag -d v1.0.0
```

7. Удаление удалённого тега:
```bash
git push origin --delete v1.0.0
```

8. Пуш конкретного тега:
```bash
git push origin v1.0.0
```

9. Пуш всех тегов:
```bash
git push origin --tags
```

10. Сортировка тегов по дате создания:
```bash
git tag -l --sort=-creatordate
```

11. Показать теги с сообщением:
```bash
git tag -n1
```

12. Показать теги, содержащие конкретный коммит:
```bash
git tag --contains abc1234
```

13. Показать теги для конкретного объекта:
```bash
git tag --points-at HEAD
```

14. Создать подписанный тег GPG:
```bash
git tag -s v2.0.0 -m "Подписанный релиз 2.0.0"
```

15. Проверить подпись тега:
```bash
git tag --verify v2.0.0
```

## Практические сценарии

**Подготовка релиза:**
Создание тега версии при выпуске нового релиза с последующим пушем на удалённый сервер.

```bash
git tag -a v2.1.0 -m "Релиз версии 2.1.0: исправлены баги, новые функции"
git push origin v2.1.0
```

**Отккат к предыдущей версии:**
Использование тегов для быстрого переключения к стабильной версии при обнаружении проблем.

```bash
git checkout v1.8.0
git checkout -b hotfix-v1.8
```

**Управление версиями в CI/CD:**
Автоматическое создание тегов при успешном завершении тестов и деплое.

```bash
VERSION=$(git describe --tags --abbrev=0)
echo "Деплой версии: $VERSION"
```

## Связки с другими командами

```bash
# Показать разницу между двумя тегами
git diff v1.0.0..v2.0.0

# Показать лог между тегами
git log v1.0.0..v2.0.0 --oneline

# Проверить стабильность перед тегом
git stash && git checkout main && git pull && git tag -a v3.0.0 -m "Релиз"

# Создать тег на основе последнего коммита в ветке
git log -1 --format="%H" | xargs git tag -a v1.2.3 -m "Релиз 1.2.3"
```

## Советы

:::tip
Используйте аннотированные теги (`-a`) для релизов — они содержат информацию об авторе, дате и сообщении, что важно для истории проекта.
:::

:::warning
При удалении тега с удалённого репозитория убедитесь, что все участники команды знают об этом, чтобы избежать конфликтов при пуше.
:::
