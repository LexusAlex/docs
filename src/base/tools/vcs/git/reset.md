# git reset

**Уровень:** Средний
**Минимальная версия Git:** 0.99

`git reset` перемещает текущую ветку и/или изменяет индекс. В режимах `--hard`, `--merge` и `--keep` команда также может менять рабочее дерево.

## Три формы команды

```bash
# Изменить индекс для выбранных путей; рабочее дерево не меняется
git reset [<tree-ish>] [--] <pathspec>...

# Интерактивно убрать части патча из индекса
git reset -p [<tree-ish>] [--] [<pathspec>...]

# Переместить текущую ветку и сбросить состояние выбранным режимом
git reset [--soft | --mixed | --hard | --merge | --keep] [<commit>]
```

Если режим не указан, используется `--mixed`.

## Режимы

| Режим | Ветка/`HEAD` | Индекс | Рабочее дерево |
|---|---:|---:|---:|
| `--soft` | изменяет | сохраняет | сохраняет |
| `--mixed` | изменяет | сбрасывает | сохраняет |
| `--hard` | изменяет | сбрасывает | сбрасывает отслеживаемые файлы |
| `--merge` | изменяет | сбрасывает с защитой локальных изменений | обновляет только допустимые пути |
| `--keep` | изменяет | сбрасывает | прерывается, если затронет локальные изменения |

::: danger `reset --hard`
Команда безвозвратно удаляет незакоммиченные изменения отслеживаемых файлов. Обычные неотслеживаемые файлы сохраняются, кроме тех, которые мешают записать отслеживаемый путь. Коммиты часто можно найти через reflog, а незакоммиченный текст — обычно нет.
:::

## Примеры

### Убрать файл из индекса

```bash
git reset -- path/to/file
git status --short
```

Рабочая копия файла не меняется. Современный явный эквивалент:

```bash
git restore --staged path/to/file
```

### Убрать из индекса часть изменений

```bash
git reset -p
git diff --cached
git diff
```

### Отменить последний локальный коммит, сохранив изменения в индексе

```bash
git log -1 --oneline
git reset --soft HEAD^
git diff --cached
```

Подходит, если коммит ещё не опубликован.

### Отменить последний локальный коммит и снять изменения с индекса

```bash
git reset HEAD^
git diff
git status --short
```

Это `--mixed` по умолчанию: файлы останутся в рабочем дереве.

### Разделить последний локальный коммит

```bash
git reset HEAD^
git add -p
git commit -m "First logical change"
git add -p
git commit -m "Second logical change"
```

Для такого сценария нужен mixed reset. После `--soft` все изменения уже были бы в индексе.

### Сбросить локальную ветку до удалённой

```bash
git fetch origin
git status --short
git branch backup-before-reset
git reset --hard origin/main
```

Создание резервной ветки делает опубликованные локальные коммиты легко восстанавливаемыми. Незакоммиченные изменения всё равно сначала сохраните отдельно.

### Восстановить индекс и рабочий файл из выбранного коммита

`reset` с путём меняет только индекс:

```bash
git reset <commit> -- path/to/file
```

Чтобы также восстановить рабочую копию, используйте `restore`:

```bash
git restore --source=<commit> --staged --worktree path/to/file
```

### Отменить слияние

Если merge ещё выполняется:

```bash
git merge --abort
```

Если merge завершился локально и после него не было важных изменений:

```bash
git show --no-patch ORIG_HEAD
git reset --merge ORIG_HEAD
```

Не подставляйте автоматически `HEAD~1`: у merge-коммита несколько родителей, а после merge могли появиться другие коммиты.

### Восстановить ошибочно сброшенный коммит

```bash
git reflog --date=local
git branch recovered-work <old-head>
```

Сначала создайте ветку восстановления. Перемещать текущую ветку через новый `reset --hard` обычно не требуется.

## Когда reset не нужен

| Задача | Более явная команда |
|---|---|
| Убрать файл из индекса | `git restore --staged <file>` |
| Отменить изменения рабочего файла | `git restore <file>` |
| Отменить опубликованный коммит | `git revert <commit>` |
| Прервать незавершённый merge | `git merge --abort` |
