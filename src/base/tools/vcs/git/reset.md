# git reset

**Уровень:** Средний
**Версия Git:** 0.99
**Версия документации:** 1.0

Сбрасывает текущий HEAD до указанного состояния. Позволяет отменять коммиты, убирать файлы из индекса и перемещать указатель ветки. В зависимости от флагов может изменять индекс (staging area) и рабочую директорию.

## Синтаксис

```bash
git reset [<mode>] [<commit>]
git reset [<mode>] [<tree-ish>] [--] <pathspec>...
git reset --patch [<tree-ish>] [--] [<pathspec>...]
```

## Основные опции

| Опция | Описание |
|-------|----------|
| `--soft` | Сбрасывает только HEAD, не изменяя индекс и рабочую директорию |
| `--mixed` | Сбрасывает HEAD и индекс, но сохраняет изменения в рабочей директории (по умолчанию) |
| `--hard` | Сбрасывает HEAD, индекс и рабочую директорию — все изменения теряются |
| `--merge` | Сбрасывает HEAD и индекс, перезаписывает неслитые файлы в рабочей директории |
| `--keep` | Сбрасывает HEAD, обновляет индекс, но останавливается при конфликтах |
| `--patch` | Интерактивно выбирает hunks для сброса |
| `-q`, `--quiet` | Подавляет вывод |
| `--no-refresh` | Не обновляет индекс после сброса |

## Примеры

### 1. Убрать файл из индекса (отменить `git add`)

```bash
# Добавили файл случайно, убираем из staging
git reset HEAD file.txt
```

### 2. Сбросить к предыдущему коммиту с сохранением изменений (--soft)

```bash
# Изменения останутся в индексе (готовы к коммиту)
git reset --soft HEAD~1
```

### 3. Сбросить к предыдущему коммиту с убиранием из индекса (--mixed)

```bash
# Изменения останутся в рабочей директории, но уйдут из staging
git reset HEAD~1
```

### 4. Полный сброс — удалить все изменения (--hard)

```bash
# ВНИМАНИЕ: все несохранённые изменения будут потеряны
git reset --hard HEAD~1
```

### 5. Сбросить к конкретному коммиту по хешу

```bash
# Сбросить на 3 коммита назад
git reset --hard abc1234
```

### 6. Сбросить конкретный файл

```bash
# Вернуть файл к версии из последнего коммита
git reset HEAD -- src/app.js
```

### 7. Сбросить несколько файлов

```bash
# Убрать несколько файлов из staging
git reset HEAD -- file1.txt file2.txt dir/
```

### 8. Интерактивный сброс (--patch)

```bash
# Выбрать конкретные hunks для сброса
git reset --patch HEAD
```

### 9. Сбросить индекс полностью

```bash
# Убрать все файлы из staging, оставив изменения в рабочей директории
git reset
```

### 10. Сбросить к определённому тегу

```bash
# Переместить HEAD на тег
git reset --hard v2.0.0
```

### 11. Сбросить merge (отменить слияние)

```bash
# Отменить неудачное слияние
git reset --merge ORIG_HEAD
```

### 12. Сбросить с сохранением локальных изменений (--keep)

```bash
# Сбросить, но сохранить локальные незакоммиченные правки
git reset --keep HEAD~2
```

### 13. Сбросить к удалённой ветке

```bash
# Сбросить локальную ветку до состояния удалённой
git reset --hard origin/main
```

### 14. Сбросить файл к версии из другого коммита

```bash
# Взять файл из конкретного коммита
git reset abc1234 -- config.yml
```

### 15. Сбросить с подавлением вывода

```bash
# Тихий режим
git reset --hard HEAD~3 -q
```

### 16. Сбросить директорию

```bash
# Сбросить все файлы в директории
git reset HEAD -- src/components/
```

### 17. Сбросить к коммиту с сохранением staged изменений

```bash
# Сохранить текущие staged-изменения, но сбросить HEAD
git reset --soft HEAD~1
git stash
git reset --hard HEAD~1
git stash pop
```

### 18. Сбросить файл к состоянию коммита из другой ветки

```bash
# Взять файл из ветки feature
git reset feature -- src/utils.js
```

## Практические сценарии

### Отмена последнего коммита с сохранением изменений

```bash
# Случайно закоммитили не то — отменяем, но сохраняем код
git reset --soft HEAD~1
# Правим staged-файлы и коммитим заново
git commit -m "Правильное сообщение"
```

### Разбиение большого коммита на несколько

```bash
# Сбросить последний коммит, оставив всё в staging
git reset --soft HEAD~1
# Теперь можно сделать несколько отдельных коммитов
git add -p
git commit -m "Часть 1: обновление API"
git add -p
git commit -m "Часть 2: обновление тестов"
```

### Отмена случайного merge

```bash
# Вернуться к состоянию до слияния
git reset --merge ORIG_HEAD
# Или жёстко сбросить
git reset --hard HEAD~1
```

### Синхронизация с удалённым репозиторием

```bash
# Перезаписать локальную историю под удалённую
git fetch origin
git reset --hard origin/main
```

## Связки с другими командами

```bash
# Сброс + новый коммит (переписать историю)
git reset --soft HEAD~1 && git commit -m "Новое сообщение"

# Сброс + stash (временно убрать изменения)
git reset --hard HEAD~1 && git stash list

# Сброс файла + checkout (полное восстановление)
git reset HEAD -- file.txt && git checkout -- file.txt

# Сброс + clean (удалить неотслеживаемые файлы)
git reset --hard && git clean -fd

# Сброс к удалённой + pull (синхронизация)
git fetch origin && git reset --hard origin/main
```

## Советы

:::tip Используйте --soft для безопасной отмены
Флаг `--soft` самый безопасный — он не удаляет изменения из индекса и рабочей директории. Используйте его, когда хотите переписать коммит.
:::

:::warning --hard удаляет изменения безвозвратно
Флаг `--hard` удаляет все незакоммиченные изменения. Перед использованием убедитесь, что всё нужное закоммичено или сохранено в stash.
:::

:::tip HEAD~N для относительных ссылок
Используйте `HEAD~N` для сброса на N коммитов назад. Например, `HEAD~3` — три коммита назад от текущего.
:::

:::warning Не сбрасывайте опубликованные коммиты
Если коммит уже отправлен в удалённый репозитий, сброс приведёт к расхождению историй. Используйте `git revert` для публичных веток.
:::
