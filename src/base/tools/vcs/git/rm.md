# git rm

**Уровень:** Начальный
**Минимальная версия Git:** 0.99

`git rm` удаляет пути из индекса и, по умолчанию, из рабочего дерева. Удаление попадёт в следующий коммит.

## Синтаксис

```bash
git rm [<options>] [--] <pathspec>...
```

## Основные опции

| Опция | Описание |
|---|---|
| `-n`, `--dry-run` | Показать, какие пути будут удалены |
| `-r` | Разрешить рекурсивное удаление каталога |
| `--cached` | Удалить только из индекса, оставить рабочие файлы |
| `-f`, `--force` | Разрешить удаление при несовпадении содержимого с `HEAD`/индексом |
| `--ignore-unmatch` | Вернуть успех, если pathspec ничего не нашёл |
| `--sparse` | Разрешить обновление путей вне sparse-checkout cone |
| `--pathspec-from-file=<file>` | Прочитать pathspec из файла |
| `--pathspec-file-nul` | Использовать NUL-разделители в файле pathspec |

Опции `-v` у `git rm` нет.

## Удалить файл

```bash
git rm -- path/to/obsolete-file
git diff --cached --stat
```

Для каталога:

```bash
git rm -rn -- old-directory/
git rm -r -- old-directory/
```

## Перестать отслеживать, сохранив файл локально

```bash
git rm --cached -- .env
git check-ignore -v .env
git diff --cached
```

До команды добавьте правило в `.gitignore` и убедитесь через `git check-ignore`, что файл действительно будет игнорироваться.

::: danger Секрет уже мог утечь
`git rm --cached` удаляет файл только из будущего снимка. Он остаётся в старых коммитах и существующих клонах. Немедленно отзовите или замените ключ/пароль; очистку истории выполняйте отдельной согласованной процедурой с повторной публикацией refs.
:::

## Удалить группу файлов

Pathspec лучше заключать в кавычки, чтобы шаблон обрабатывал Git, а не оболочка:

```bash
git rm -n -- '*.log'
git rm -- '*.log'
```

Только внутри каталога:

```bash
git rm -n -- 'logs/*.log'
git rm -- 'logs/*.log'
```

## Удалить уже отсутствующие рабочие файлы из индекса

```bash
git rm -n --cached --ignore-unmatch -- path/to/file
git rm --cached --ignore-unmatch -- path/to/file
```

Для массовой синхронизации индекса с удалениями часто достаточно:

```bash
git add -u
git diff --cached
```

## Если файл изменён

Git обычно откажется удалять файл, если staged/working версия не совпадает с ожидаемой. Сначала посмотрите изменения:

```bash
git diff -- path/to/file
git diff --cached -- path/to/file
```

Сохраните нужное коммитом или stash. `git rm -f` применяйте только когда изменения точно не нужны.

## Отменить удаление до коммита

```bash
git restore --staged -- path/to/file
git restore -- path/to/file
```

Первая команда возвращает путь в индекс из `HEAD`, вторая восстанавливает рабочий файл из индекса.

## Переименование

Для переноса отслеживаемого файла используйте:

```bash
git mv old-name new-name
```

Git хранит снимки, а не отдельный объект «переименование», но `git mv` удобно синхронно меняет рабочее дерево и индекс.
