# Блочные и строчные элементы

В современном HTML нет нормативных категорий «блочный элемент» и «строчный элемент». Эти слова обычно описывают начальное CSS-представление элемента, а не его семантику или допустимых потомков.

## Модель содержимого HTML

Для каждого элемента спецификация определяет:

- категории содержимого, к которым элемент относится;
- контексты, в которых его можно использовать;
- модель содержимого — допустимые дочерние узлы;
- дополнительные ограничения, зависящие от атрибутов и окружения.

Например, `ul` принимает пункты `li`, а `picture` содержит `source` и завершающий `img`. Внешний вид этих элементов не меняет их структурные правила.

Основные категории включают `metadata`, `flow`, `sectioning`, `heading`, `phrasing`, `embedded`, `interactive` и `palpable`. Один элемент может входить сразу в несколько категорий, иногда только при выполнении условия.

Смотрите [индекс элементов по категориям](../by-category) и нормативный раздел [Content models](https://html.spec.whatwg.org/multipage/dom.html#content-models).

## Отображение CSS

CSS создаёт box tree для раскладки. Значение `display` определяет внешний и внутренний тип отображения: например, блоковый или строчный внешний поток, flex/grid-контейнер либо отсутствие собственного бокса.

Один HTML-элемент может:

- создавать один или несколько CSS-боксов;
- не создавать собственного бокса при `display: contents`;
- не участвовать в отображении при `display: none`;
- отображаться блоково или строчно независимо от своей HTML-категории.

```html
<a class="card" href="/article">Статья</a>
```

```css
.card {
  display: block;
}
```

Ссылка остаётся элементом `a` с прежней HTML-семантикой и ограничениями, хотя CSS делает её внешнее представление блоковым.

## Почему старое деление вводит в заблуждение

Утверждение «блочный элемент может содержать блочные и строчные, а строчный — только строчные» не является правилом HTML. Например:

- `a` использует прозрачную модель содержимого и при некоторых контекстах может оборачивать потоковое содержимое, но не должен содержать интерактивных потомков;
- `p` допускает фразовое содержимое, поэтому `div` внутри `p` недопустим, даже если его CSS изменить на `display: inline`;
- `span` остаётся универсальным фразовым контейнером, даже если ему назначить `display: block`.

```html
<!-- Недопустимая структура: CSS не исправляет модель содержимого p. -->
<p><div>Карточка</div></p>
```

HTML-парсер к тому же автоматически закроет `p` перед `div`, поэтому итоговое DOM-дерево будет отличаться от исходной записи.

## Практическое правило

1. Выбирайте HTML-элемент по смыслу и проверяйте его контекст и модель содержимого.
2. Используйте CSS для раскладки и визуального представления.
3. Проверяйте итоговое DOM-дерево, доступность и валидность, а не только внешний вид.
